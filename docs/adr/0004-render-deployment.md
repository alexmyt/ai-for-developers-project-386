# 0004 — Деплой на Render

- **Статус:** принято
- **Дата:** 2026-11-14

## Контекст

Приложению нужна публичная ссылка для проверки сценария гостя и владельца.
Бюджет учебного проекта нулевой, эксплуатация должна быть минимальной,
а состояние и так живёт в памяти одного процесса (ADR-0003) — база данных
и постоянный диск не нужны.

## Решение

- **Хостинг — Render**, web service из GitHub-репозитория. Конфигурация
  сервиса объявлена blueprint-файлом `render.yaml` в корне: имя, регион,
  план, путь health check.
- **Runtime — Docker.** В репозитории уже есть multi-stage Dockerfile
  (сборка монорепозитория → производственный образ), и он же проверяется
  контейнерным e2e. Нативная Node-среда повторила бы его шаги командами
  build/start и потребовала бы настраивать `WEB_STATIC_ROOT` под рабочую
  директорию Render.
- **Одна услуга, один домен.** NestJS отдаёт и API, и статику SPA
  (ADR-0002), SDK ходит по относительным путям `/api/...` — раздельный
  хостинг фронта потребовал бы прокси, а проксирование уже решено
  `ServeStaticModule`.
- **План Free, регион Frankfurt.** Инстанс засыпает после ~15 минут без
  трафика; первый запрос после сна занимает до минуты.
- **Деплой через MCP Render.** Сервер `https://mcp.render.com/mcp` подключается
  агентам (конфиг — `opencode.json`, инструкция — `docs/agents/render.md`).
  OAuth-сервер Render принимает только клиенты из официальных плагинов
  (Claude Code, Codex, Cursor) и не поддерживает динамическую регистрацию,
  поэтому OpenCode аутентифицируется API-ключом через переменную окружения
  `RENDER_API_KEY` — секреты в git не попадают.

## Рассмотренные альтернативы

- **Нативная среда Node на Render** — дублировала бы Dockerfile командами
  и добавила бы зависимость от раскладки каталогов Render.
- **Две услуги (статический сайт + API)** — нужен реверс-прокси или CORS:
  фронтенд вызывает `/api` с тем же домена.
- **Другие платформы (Fly.io, Railway)** — сопоставимы, но у Render есть
  hosted MCP-сервер и blueprint-спецификация, а бесплатный Docker-план
  закрывает задачу без карты.

## Последствия

- Все данные теряются при любом завершении процесса: рестарт, редеплой,
  засыпание Free-инстанса (ADR-0003). Это отражено в README.
- Холодный старт до минуты учитывается в e2e: прогон против развёрнутого
  инстанса включается переменной `E2E_BASE_URL` и получает увеличенный
  таймаут навигации.
- Деплой ведётся от `render.yaml`: blueprint-инструменты MCP (public alpha)
  создают, планируют и применяют сервис из файла; план изменений сначала
  показывается человеку и применяется только после его подтверждения.
