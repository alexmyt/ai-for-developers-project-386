# 0001 — Стек проекта

- **Статус:** принято
- **Дата:** 2026-11-04

## Контекст

Учебный проект «Календарь звонков»: SPA для гостя и минимальные экраны
владельца, API на NestJS, состояние в памяти, TypeSpec-контракт как источник
истины, один Docker-образ. Авторизации и базы данных нет, владелец календаря
один. Требования фиксируют NestJS актуальной версии, отсутствие БД и запуск
в контейнере.

## Решение

Монорепо на pnpm workspaces:

```
apps/api            NestJS 12 + TypeScript 6
apps/web            React 19 + Vite 8 + TypeScript
packages/contract   TypeSpec 1.17 → openapi.json (OAS 3.0)
packages/sdk        клиент, сгенерированный @hey-api/openapi-ts
```

- **Фронтенд:** React 19 + Vite (SPA), `react-router` 8 в declarative-режиме,
  TanStack Query 5 для серверного состояния, Tailwind CSS 4 + shadcn/ui
  точечно, React Hook Form + Zod для форм, `date-fns` + `@date-fns/tz`.
- **Бэкенд:** NestJS 12, Express-платформа, `ServeStaticModule` для статики,
  `async-mutex` для сериализации бронирований.
- **Контракт:** TypeSpec 1.17 с эмиттером OpenAPI 3.0; сгенерированный
  `openapi.json` коммитится в репозиторий.
- **Качество:** ESLint 10 (flat config) + Prettier 3, Vitest 5 во всех
  пакетах, supertest + ajv для контрактных e2e-тестов.
- **Доставка:** один multi-stage образ `node:22-alpine`, pnpm через corepack,
  запуск от non-root пользователя, порт 3000, HEALTHCHECK на `/api/health`.

TypeScript зафиксирован на мажоре 6, а не 7: `@nestjs/cli` 12 ставит
`typescript@~6.0.2`, и совпадение версий компилятора в сборке и в CLI
избавляет от расхождений в поведении декораторов.

## Рассмотренные альтернативы

- **Next.js / SSR** — в сценарии нет SEO-задач, состояние живёт в памяти
  одного процесса, весь UI интерактивный. SSR добавил бы второй рантайм
  и усложнил бы контейнер без выгоды.
- **npm workspaces / плоская структура** — pnpm даёт строгие зависимости
  и единый lockfile, а контракт и SDK естественно становятся пакетами.
- **MUI / Chakra** — готовые компоненты навязывают свой дизайн-язык;
  в референсе из видео важна конкретная структура экрана, её проще повторить
  на Tailwind.
- **Jest для API** — Vitest даёт один раннер и один конфиг на монорепо,
  без трансформаций и `ts-jest`.
- **Playwright** — happy-path проверяется вручную и записывается
  в asciinema; сквозной браузерный тест замедлил бы CI.

## Последствия

- Фронтенд и бэкенд делят один контракт и один сгенерированный клиент —
  расхождение типов ловится на этапе сборки.
- Один образ и отсутствие CORS упрощают запуск: `docker run -p 3000:3000`.
- Константы календаря (таймзона, часы работы, окно 14 дней) живут в
  `apps/api/src/config` и задокументированы в спеке; фронтенд их не
  дублирует.
- Владельческие эндпоинты открыты: авторизация вне объёма сценария
  (см. README).
